# Windows ARM64와 전체 WACK 통과 릴리스 설계

## 배경과 목표

사용자는 선택 WACK 검사까지 통과하는 새 후보를 충분히 검증한 뒤 API로
Microsoft Store에 제출하도록 요청했고, Windows ARM64 네이티브 지원을 같은
릴리스에 추가했다. 기존 공개 Store 버전은 1.1.1.0이다. 새 버전은 아직 정규
태그가 없는 1.1.3(패키지 1.1.3.0)이며 과거 x64 Source68을 새 후보 증거로
재사용하지 않는다.

## 제품·검증 범위

- x64 지원을 유지하고 ARM64 GUI와 CLI를 별도로 소스 빌드한다. ARM64EC나
  x64 에뮬레이션 실행을 ARM64 네이티브 성공으로 기록하지 않는다.
- 실제 ARM64 Windows에서 GUI·CLI의 PE machine 0xAA64와 제품 PID의
  IsWow64Process2 결과(processMachine=0, nativeMachine=0xAA64)를 확인한다.
- 기존 편집·저장·암호·PDF·파일 연결·설치·제거·가상 인쇄 검사를 유지한다.
  물리 프린터와 모든 문서의 무결함을 주장하지 않는다.
- Telemetry 수집 코드·SDK·전송 경로를 이번 릴리스에 추가하지 않는다.
- 한국어 안내, 자동 업데이트 기본 ON·시작 및 매시간 확인, 사용자 동의 후
  Store 열기와 무료 가격을 유지한다. 사용자의 새 지시에 따라 이번 Store
  제출은 인증 후 자동 공개(`Immediate`)한다.

## 아키텍처와 출처 계약

지원 아키텍처는 정확히 x64와 arm64이다. Rust target은 각각
`x86_64-pc-windows-msvc`, `aarch64-pc-windows-msvc`이며 PE machine은
0x8664, 0xAA64이다. 매니페스트·실행 파일·구성 요소·패키지·출시 메타데이터의
아키텍처가 일치해야 한다. 알 수 없는 아키텍처·혼합 패키지·다른 소스/실행의
구성 요소는 파일 생성·설치·업로드 전에 거부한다.

WASM과 프런트엔드는 동일 소스 입력에서 한 번 준비하고 두 아키텍처가 공유한다.
네이티브 구성 요소와 전체 런타임 해시는 아키텍처별로 기록한다. 각 아키텍처의
unsigned MSIX와 portable 전체 런타임 일치를 계속 강제한다. 아키텍처별 출력
디렉터리를 분리해 이름 충돌이나 기존 산출물 덮어쓰기를 막는다.

공개 저장소의 무료 표준 `windows-11-arm` 러너를 사용한다. 테스트 컨트롤러가
x64 Python을 사용하는 경우에도 제품 바이너리의 실제 네이티브 여부를 별도로
확인한다. SDK와 빌드 도구의 아키텍처를 제품 아키텍처로 혼동하지 않는다.

## WACK 실패 원인과 통과 조건

Source68의 선택 Blocked executables 검사 13개 메시지는 실행 API 참조 3개와
이름 참조 10개다. SDK 10.0.26100.8249의 실제 IL에서 패키지 전체 launch API
검사 뒤 false이면 이름 검사를 호출하지 않는 분기를 확인했다. 이름 참조에는
명령 실행과 관계없는 기계어와 문서 문자열이 있다. 문자열 숨기기·PE 수정·SDK
수정·검사 제외·판정기 완화는 해결책으로 사용하지 않는다.

Windows URL·PDF·폴더 열기는 OS 활성화 API를 사용하고 실제 실패를 반환한다.
Tauri의 사용하지 않는 self-restart 경로와 오류 대화상자의 셸 호출을 함께
검토한다. CLI MCP 작업자의 실패 격리와 암호/stdin·JSON 출력·종료 코드 계약을
약화하지 않는다. 사용자는 MCP 서버와 별도 프로세스의 실패 격리 유지를
명시적으로 선택했다. Windows COM이 소유 작업자 프로세스를 실행하도록 하고,
명령·암호·환경은 인증된 로컬 파이프로 전달하는 경로를 검증한다. 기존 암호 stdin,
상대 경로, JSON 출력, 부분 실패 종료 코드와 서버 생존 계약을 유지한다.
패키지의 COM 등록과 portable의 임시 등록을 구분하며 기존 등록을 덮어쓰지 않는다.
PID·실행 파일·사용자·로그온 세션·권한과 통신 상대가 일치하기 전에는 문서 입력을
보내거나 작업자 프로세스를 종료하지 않는다.

SDK 정상 전체 실행, 예상 identity·version·서명 테스트 입력 SHA, 필수 및 선택
검사 모두 PASS, `passed=true`, `nonPassingTests=[]`가 최종 조건이다. WACK
unavailable·부분 실행·경고·선택 FAIL을 소스 릴리스와 Store 제출에서 차단한다.
개발 identity의 결과와 Store identity의 결과를 구분하고 양쪽 아키텍처의 실제
Store 패키지도 임시 서명 사본으로 검증한다. unsigned 원본 바이트는 보존한다.

## Store 제출과 공개 상태

동일 정규 태그·소스·전체 실행·버전의 x64와 ARM64 unsigned MSIX 두 개를 한
submission의 applicationPackages 배열로 제출한다. bundle은 필수로 도입하지
않는다. 두 패키지의 해시·크기·아키텍처 집합을 재시도 journal과 마커에 묶고,
불확실한 쓰기를 새로운 submission으로 반복하지 않는다.

원본은 아키텍처별 96MiB 상한과 고정 두 아키텍처의 전체 상한을 적용한다.
Store 업로드 ZIP의 기존 96MiB 상한은 실제 두 MSIX의 합계와 비교한다.
무제한 크기 상향·원본 재압축으로 검증을 피하지 않는다.

공개 상태 관측기는 과거 x64-only와 새 정확한 x64+arm64 동일 버전 집합을
구분해 허용한다. unknown architecture·중복·혼합 버전·미공개 상태는 거부한다.
앱과 웹사이트의 공개 메타데이터 formatVersion 1·정확한 6필드는 유지한다.

## 검증·복구

아키텍처 혼합·PE/매니페스트 불일치·출처 바꾸기·WACK 경고 수용·부분 제출·
공개 버전 회귀에 실패하는 검사를 먼저 실행하고 수정 후 성공을 기록한다.
최종 같은 후보의 Windows·브라우저·인쇄·설치·전체 WACK 결과와 공개 파일
해시를 독립 검토한 뒤 정규 v1.1.3 태그의 새 전체 실행을 사용한다.

Store는 브라우저 없이 API로 작업한다. 최신 App·Published·pending 상태를
확인하고 무료 가격·한국어 소개를 보존하며 새 제출의 공개 방식을
`Immediate`로 설정해 commit을 한 번 실행한다. 기존 Published 기준 제출의
`Manual`/`Immediate`는 읽을 수 있지만 새 요청의 PUT·commit 직전 조회와
같은 SID의 처리 결과는 `Immediate`여야 한다.
접수·처리 상태와 제출 ID를 확인하며 제출을 인증·게시 완료로 바꾸어 보고하지
않는다. 실패 시 기존 공개판과 출시 태그를 보존하고 불확실한 쓰기의 상태를
조회한 뒤 복구한다.
