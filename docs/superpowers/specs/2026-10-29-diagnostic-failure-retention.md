# Preserve bounded diagnostic failures

An original ARM64 Writer callback was complete and below its frame cap, with a
bound product frame, but an exception in selection, the file-only symbol worker
or their join left both outer results unset. The numeric projection consequently
cannot identify the failed operation. An independent normal run also failed the
native archive member gate without identifying its failed assertion.

Preserve completed selection before invoking the worker. Keep the original
selector, worker and join assertions and propagate the original exception. Emit
one existing kind-1 numeric failure with an append-only operation stage and owned
source frames. Do not add a compartment model or carrier, export error strings,
accept partial worker results, repeat native calls or change budgets or input.

If the original join returns normally after its identity, frame and tag checks,
retain that checked worker receipt even when its final boolean is false because
a tag is unresolved. Keep the original assertion failure. Worker exceptions and
join assertion failures do not publish a worker result. The existing model can
distinguish a successful file-only query with unresolved tags from worker failure;
it does not publish arbitrary symbol names or source lines.

For archive members, add stage assignments before the existing completion,
list, path, containment, size and hash assertions. Preserve the assertions and
filesystem calls byte-for-byte at the AST level. Preserve all existing numeric
identifiers and append new ones. File names, document content and input are not
needed for either observation.

Synthetic tests must inject selector, worker and join failures and distinguish
damaged archive conditions using the actual workflow verifier. Exact-source
Windows execution remains necessary. A diagnostic cannot qualify a product ZIP;
final paired normal acceptance remains required. Do not expand symbol aliases
without matched file evidence or weaken focus, ownership or cleanup guards.
