# Portable package acceptance

The Suite delivery contract is a ZIP extracted into a fresh folder. Verify the
final ZIP and run the existing Windows acceptance against its extracted bytes.
The baseline package, original HWP assets, runtime locks and release channels
remain intact.

Authenticate every archive member against the fully verified staged inventory
before creating outputs. Reject aliases, links, unexpected members, corrupt
bytes and intersecting paths. Extract to a fresh Korean and spaced path, verify
it, and record creation before changing one owned Office file. Require the
inventory verifier to detect that change. Extract the same authenticated ZIP to
a new sibling folder, then verify the repaired copy and preserved baseline.
Measure HWP file hashes in all copies.

The file receipt reports relocation, coexistence of the same version and repair
by clean extraction. Version upgrade and unsaved-document recovery remain
unverified. GUI evidence comes from the existing Windows gates against the clean
extraction, including all 40 startup attempts from an owned working directory
outside the payload. Each child inherits its ordinary process environment;
the controller's working directory and environment remain unchanged.

Run this check inside the existing acceptance build step. A failure rejects that
step and retains existing downstream prerequisites. Preserve the original ZIP
path for final artifact upload, the extracted root for subsequent verification,
and the file receipt with acceptance evidence. Retain all existing runner,
privacy, source ownership, deadline and nonacceptance conditions.
