# HWPX 저장 및 E2E 구현 계획

> 이 문서는 2026-10-05 작성 당시의 계획과 점검 상태를 보존한 기록입니다. 체크박스와 검증 수치는 당시 기준이며, 이후 릴리스의 완료 상태를 뜻하지 않습니다.

**목표:** HWPX 편집·저장 기능과 릴리스를 차단할 수 있는 충분한 테스트를 무료 표준 실행기에 추가한다.
**구조:** 기존 배포용 오버레이를 적용한 뒤 검증된 확장을 적용한다. HWP 경계는 유지하면서 네이티브 형식별 저장과 실제 WASM 내보내기를 사용한다. 정확한 프로덕션 페이로드와 프로덕션 웹 프런트엔드를 테스트한다.
**기술 구성:** Rust/Tauri, TypeScript, Python unittest/Playwright, Windows UI Automation, GitHub Actions.
**사양:** ../specs/2026-10-05-hwpx-e2e.md

## 제약과 검토 중점

소스 고정 버전, MIT 고지, 설치된 글꼴만 사용하는 정책과 서명되지 않은 개발 상태를 유지한다. 기능 지원을 주장하려고 기존의 실패하는 검증을 비활성화하지 않는다. 오래된 리비전, 유효하지 않은 바이트, 외부 변경, 대화상자 취소, 저장 중 편집 경합, 유니코드·대문자 경로와 지원하지 않는 확장자를 확인한다. 픽스처와 아티팩트에 사용자 문서나 글꼴 바이너리를 포함하지 않는다.

## 작업

- [x] 파일 이름 테스트의 실패를 확인하고 형식 선택을 구현한 뒤, 로컬 Node 테스트 14개의 통과를 확인한다.
- [ ] 변경하지 않은 업스트림에서 실패가 예상되는 HWPX 원본 저장 테스트를 실행하고, 진단 후 원래 테스트를 복원한다.
- [ ] 네이티브 IPC와 세션 저장을 확장한다. Windows에서 실제 HWPX 파싱·쓰기·다시 열기와 오류 발생 시 상태 보존을 테스트한다.
- [ ] WASM HWPX 내보내기와 다른 이름으로 저장 필터를 연결하고, 비동기 저장 중 발생하는 편집을 보존한다.
- [ ] 합성 픽스처를 생성하고 독립적인 ZIP/XML 검증기로 확인한다.
- [ ] 프로덕션 바이너리를 사용하는 네이티브 Windows UI 테스트와 여러 브라우저의 프로덕션 프런트엔드 테스트를 추가한다.
- [ ] 릴리스 전에 모든 E2E 작업을 필수로 요구한다. 증거 아티팩트 크기를 제한하고 서명이나 유료 실행기 자격 증명을 사용하지 않는다.
- [ ] 실제 CI 결과를 읽고 실패를 수정한다. 검증된 범위와 남은 범위를 정확히 기록하며, 통과한 커밋만 릴리스한다.
