# ARM64 and Office feature E2E implementation plan

> **For agentic workers:** Use superpowers:subagent-driven-development for isolated implementation and independent review. Root integrates and owns remote CI and delivery.

**Goal:** Produce source-bound x64/ARM64 portable builds with architecture-correct native verification and a concrete feature coverage catalogue.

**Architecture:** Share the shell and worker while selecting fixed architecture locks, native MSI members and strict payload machine validation. Retain existing native tests and add a separate semantic feature suite.

**Tech Stack:** Python 3.12+, .NET 8, WinForms, LibreOffice UNO, PowerShell, GitHub Actions native Windows runners.

**Spec:** docs/superpowers/specs/2026-10-17-office-arm64-e2e.md

## Global constraints

- Start at verified source 80c722c00377189495c3731c3b507d402bbbb6c2.
- Version 0.2.0-dev; upstream Office 26.8.1.1 and HWP 1.1.4.
- No main merge, public release, original artifact overwrite or weaker x64 gates.
- Native x64 is 0x8664, native ARM64 is 0xAA64; unknown architectures fail closed.
- Tests operate only on private generated documents and owned processes/profiles.

## Review focus

- An ARM64-labelled package must reject x64 shell/runtime/HWP/CRT bytes.
- Inventory/provenance/source lock mismatches must fail independently of filenames.
- Compiler/controller/IME mismatch must fail before a hook is loaded.
- Lossy plain formats need explicit different semantic expectations.
- Missing/duplicate/failed feature cases and abnormal process cleanup block qualification.
