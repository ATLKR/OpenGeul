# 릴리스 준비 상태와 후보 수정 기록

## 2026-10-12 — x64·ARM64와 전체 WACK 목표 진행 중

새 후보는 MCP 서버의 별도 작업자·실패 격리를 유지하며 x64와 ARM64를
네이티브로 함께 지원하도록 준비하고 있습니다. 선택 검사를 포함한 전체 WACK,
실제 휴대용·설치 MCP와 새 정규 태그의 전체 소스 실행을 통과한 뒤 두 패키지를
Store API로 제출합니다. 가격은 무료로 유지하며 이번 새 제출은 인증 통과 후
자동 공개(`Immediate`)하도록 설정합니다.

별도 Windows COM 진단과 파일·폴더 활성화 진단은 두 아키텍처에서 통과했지만,
실제 rhwp 제품·설치 MSIX·전체 WACK 통과를 뜻하지 않습니다. 새 후보의 제품
검증과 Store 제출은 아직 완료하지 않았습니다. 아래 Source68 기록은 이전
x64 후보에만 적용됩니다. 진행 기준은 [다음 릴리스 목표](NEXT_RELEASE_GOAL.md)를
따릅니다.

### 실제 Source75 결과와 남은 수정

[Source75](https://github.com/ATLKR/OpenGeul/actions/runs/38237687615)는 소스
`f104fd4080214bc072cf39a24e73454685dd4254`의 시도 1이며 전체 결과는 실패입니다.
실제 작업 21개 중 성공 16개, 실패 3개, 건너뛰기 2개를 확인했습니다.
Windows 2022 파일 선택기의 사라진 자식 HWND, ARM64 인쇄 미리보기의 여백
옵션 대기, ARM64 러너의 WACK 도구 부재가 남았습니다. 릴리스는 생성하지
않았으며 이 실행을 새 후보의 전체 통과로 사용하지 않습니다.

ARM64 설치 후보의 GUI·WebView2·CLI와 설치된 MCP의 문서 작업 17개·64개
일괄 요청은 네이티브로 완료됐습니다. WACK가 실행되지 않았으므로 설치 작업
전체의 통과를 뜻하지 않습니다. 인쇄는 ARM64 8개 중 7개가 통과했고 남은
사례는 PDF 출력 이전의 미리보기 설정에서 실패했습니다. 인쇄 기준과 허용
오차는 유지합니다.

[별도 SDK 진단](https://github.com/ATLKR/OpenGeul/actions/runs/38247515867)에서는
x64 표준 러너의 원본 Microsoft WACK가 ARM64 패키지 입력의 필수 13개·선택
11개를 모두 통과했습니다. 이 결과는 SDK의 검사 가능성에만 적용됩니다.
새 후보에서는 ARM64 네이티브 설치와 x64 WACK가 같은 테스트 서명 MSIX를
검사하도록 연결하고 두 작업을 모두 필수 조건으로 검증합니다. 과거 진단
패키지나 다른 서명 바이트로 새 후보의 통과를 대신하지 않습니다.

### 현재 제공 범위와 후속 연구

현재 Windows 편집기는 Tauri·WebView2와 WASM 편집 화면을 사용합니다. 두 Windows 이미지의 실제 GUI·저장·암호·가상 인쇄와 Windows 2025의 설치·제거 결과, WebView2 부재 안내의 제한된 실행 범위를 확인했습니다. 가상 프린터 통과는 실제 물리 프린터 전체의 검증이 아니며, Windows IME·문서 접근성·임의의 손상 문서·모든 글꼴과 문서의 충실도는 별도 근거가 필요합니다. WACK는 필수 13개 통과와 선택 `Blocked executables` 검사 1개 FAIL의 원문 메시지 13개를 함께 보존하며 완전한 WACK PASS나 Store 승인을 주장하지 않습니다.

Telemetry는 [준비 문서](TELEMETRY_PREPARATION.md)만 추가했습니다. 현재 후보에 Telemetry SDK·런타임·이벤트 수집·수집 endpoint를 추가하지 않았습니다. 공개 Store 버전 GET과 문서 내용·사용자 추적 수집을 구분하며, 미래 Telemetry의 목적·동의·필드는 별도 검토와 구현 승인을 거쳐야 합니다.

WebView 없는 Windows 화면은 [네이티브 Windows 연구](NATIVE_WINDOWS_FEASIBILITY.md)에 정리한 후속 시험 단계입니다. Rust 엔진 재사용 가능성과 UI·IME·접근성·인쇄 이식량을 조사했으며, 실제 성능 향상 수치를 측정하지 않았습니다. 후보의 현재 WebView2 기반 검증 결과를 미래 WinUI·Skia 화면의 성능·호환성 근거로 사용하지 않습니다.

## 2026-10-06 — 이전 1.1.1 인쇄 후보 수정 기록

### 원인과 제한된 수정

실패한 Windows 2022 스풀러 PDF는 용지가 A4였지만 내용이 축소되고 이동했습니다. 독립 PDF 검사에서 흰 페이지 경로가 (0.24,0)-(595.32,841.92) 대신 (25.44,35.76)-(571.44,807.00)에 있었고 글리프·연산자 수는 유지됐습니다. 네이티브 미리보기 검사에서는 A4 시스템 드라이버 대화상자 전에 Letter 용지와 Default 추가 여백이 확인됐습니다. 두 단계를 모두 명시적으로 설정했습니다. 미리보기는 A4, 추가 여백 없음, 실제 크기를 사용하고 실제 드라이버는 A4 세로를 유지합니다.

WebView2 153은 드롭다운을 ComboBox로 노출하고 이전 Runtime은 이름이 있는 Button을 사용합니다. 두 방식 모두 네이티브 ExpandCollapse와 ListItem 옵션을 제공합니다. SelectionItem.Select는 Collapse를 하지 않아도 새 미리보기의 값을 확정하지 못했습니다. 네이티브 옵션을 한 번 클릭하고 확정 값을 다시 읽으면 적용됐습니다. 소유한 시스템 인쇄 동작은 실제 UIA InvokePattern을 한 번 사용해 작은 화면에서의 키보드·클릭 시점 문제를 피합니다. 앱 테스트 훅, 직접 PDF 우회나 보안 플래그는 없습니다.

### 실제 진단 근거와 최종 후보 빌드의 구분

- Windows 2022 진단 37443984734: 미리보기 설정 후 원래의 정확한 지문으로 네이티브 인쇄 시나리오 8개가 모두 통과했습니다.
- 단일 사례 진단 37445466435: 옵션 클릭 수정 후 두 Windows 이미지에서 HWPX 인쇄가 성공했습니다.
- 전체 사례 진단 37445818877: Windows 2022는 8/8, Windows 2025는 7/8이 통과했습니다. 남은 사례는 아래의 독립 검토된 글리프 변형이며 누락된 줄이나 스풀러 실패가 아니었습니다.
- 이 진단 실행은 소스 0aedc704fe75b996bfa86f666f23e4297071de83의 PR4 바이너리 375a067e7d0ecdbb16c8efbd16760335172849003b7584218adc00b668c818ce를 재사용했습니다. 최종 전체 워크플로의 동일 실행 후보 테스트를 대체하지 않습니다.

### 비교 완화 대신 명시적인 기준 검토

실행 37445818877, 산출물 11403760205의 Windows 2025 table-0 출력은 원래 출력과 A4 크기, 경계, 텍스트, 표 테두리와 배치가 같았습니다. 두 PDF 페이지 스트림 모두 연산자 1,858개를 포함했고 바뀐 피연산자 10개는 숫자 4 하나의 가로획 좌표뿐이었습니다(-2.24/-3.37 대 -2.40/-3.36). 행 5개와 마지막 하강부가 시각적으로 온전했습니다. 216 DPI에서 [479,388,490,389]의 임계값 처리 픽셀 정확히 8개만 달라졌습니다.

모든 원래 지문을 유지하고 실행·산출물·검토 출처를 갖춘 독립 검토된 전체 페이지 변형 하나만 table-0의 1쪽으로 제한해 추가했습니다. 검토하지 않은 해시, 다른 사례·페이지, 경계 변경, 검토 누락, 중복 변형과 달라진 픽셀은 계속 실패합니다. 일반적인 픽셀 허용 오차나 후보에서 만든 기준은 없습니다. 실제 Windows 2025 출력 PDF 7개를 이 고정 기준으로 다시 읽었을 때 독립적인 형태·래스터 검사를 통과했습니다. 새 CI에서도 실제 인쇄 경로를 실행해야 합니다.

### 로컬 검토와 최종 검증

새 설정·순서·동작 테스트가 수정 전에 실패하는 것을 확인했습니다. 당시 전체 로컬 정책 테스트 150개, CI 도우미 테스트 81개, 독립 PDF·래스터 테스트 31개가 통과했습니다. 마지막 집합에는 검토된 변형의 음성 대조군 8개가 포함됩니다. 기존 인쇄 출력 저장 도우미와 정확한 HWND의 오류·파일 대화상자 수정을 유지했습니다.

당시 최종 제품 패치 버전은 1.1.1(MSIX 1.1.1.0)이었습니다. 인쇄 테스트 도구 수정은 앱 기능을 바꾸지 않았고, 릴리스 노트는 이미 구현된 HWPX 저장을 올바르게 안내하도록 정리했습니다. 병합·게시 전 최종 후보에서 전체 소스 빌드, UI 실행 78회와 MSIX 설치가 통과해야 했습니다. 이 문서는 당시 대기 중이던 최종 실행을 성공으로 표시하지 않습니다. 세션 안에서 검토했으며 독립 또는 하위 에이전트 리뷰를 받았다고 주장하지 않습니다. 이후 후보의 성공 근거로 사용하지 않습니다.
