사용자의 계속 개선 요청에 따라 **다음 후보의 저장·종료 결함과 Windows
인쇄 CI 실패를 재현하고, 수정·독립 검토·실제 Windows 검증까지 완료하는
것**을 새 목표로 삼습니다. 제출된 1.1.3의 태그와 공개 파일은 보존합니다.
새 후보의 버전·태그는 수정과 검증 범위가 확정된 뒤 결정합니다.

현재 main `72beaae4229069bb6700314ce77bdc53ce6e5f51`의 CI83은 통과했으나
[Source100](https://github.com/ATLKR/OpenGeul/actions/runs/38343222054)은
Windows 세 환경의 인쇄 검사에서 실패해 전체 성공으로 판정하지 않습니다.

대체하지 않습니다. 업데이트·문서 저장·MCP 처리도 독립 검토합니다.

Windows x64·ARM64의 별도 COM 진단에서는 각각 네이티브 권한 검사 8개,
프로토콜 검사 8개와 실제 별도 프로세스 시나리오 11개가 통과했습니다.

통과 근거가 아닙니다. 일반 사용자·UAC 비활성화 실행도 이 결과에 포함하지 않습니다.
[파일·폴더 진단 실행 26](https://github.com/ATLKR/OpenGeul/actions/runs/38199493390)도
두 네이티브 아키텍처에서 운영체제의 활성화 수락을 확인했습니다. 외부 앱의
표시 내용이나 렌더링 속도를 검증한 결과는 아닙니다.

제품 통합 후 실제 휴대용·설치 MCP, 두 아키텍처의 전체 WACK와 새 정규
태그의 전체 소스 검증을 새 실행으로 수행합니다. 이전 후보의 증거를 새 후보의

앱 소스 `b3c8b61d01731dc1e39357034d9c489a3ea829a9`의
[Source68](https://github.com/ATLKR/OpenGeul/actions/runs/38181680763) 필수 작업 15개가

웹사이트는 Store 바로가기·공개판 배지·새 개발판 링크를 배포했습니다.
앱의 자동 확인은 기본 ON이며 시작 시와 이후 매시간 실행하고, 설정에서 끄거나

[Store 실행 17](https://github.com/ATLKR/OpenGeul/actions/runs/38185086797)의

2026-10-12 00:12:28 UTC 게시했으며 서버 크기·SHA256을 원본과 대조했습니다.
HOP 0.4.5와 rhwp 0.8.7은 공식 최신 릴리스와 다시 대조했습니다.

**아래 내용은 이전 개발 후보 당시 기록이며, 현재 접수 상태는 상단의 2026-10-13 기록을 따릅니다.**

## 완료 기준

- 개인 웹사이트에서 공식 상품 9PJH0T3PHRMF의 Store 설치 링크를 제공합니다.
  공개판·개발판을 구분하고 개인 Cloudflare의 Git 빌드 소스·배포 버전·공개
  응답 바이트가 일치해야 합니다.
- 앱 안내·Store 소개·README·릴리스 노트·배포 문서는 한국어를 우선합니다.
  Store 공개 버전 배지를 확인된 공개 상태에 따라 갱신할 수 있어야 합니다.
- 업데이트 확인은 기본으로 켜고 앱 시작 시와 실행 중 매시간 수행합니다.
  자동 확인을 끄거나 수동으로 확인할 수 있어야 합니다. 새 공개판을 발견하면
  한국어로 안내하고 사용자가 선택했을 때 고정된 Store 페이지를 엽니다.
  문서 작업을 막거나 다운로드·설치·종료·재시작을 강제로 수행하지 않습니다.
- Telemetry는 미래의 명시적 동의를 전제로 설계 문서와 후속 작업만 준비하며
  1.1.3에 수집 코드·SDK·전송 경로를 포함하지 않습니다. Windows 전용 native
  화면은 현재 코드의 재사용 경계·입력·접근성·성능 측정 계획을 조사합니다.
- HOP/rhwp 버전·커밋을 공식 최신 릴리스와 대조하고 고정을 유지하는 호환성
  근거를 기록합니다. 업스트림 바이너리로 자체 소스 빌드를 대체하지 않습니다.
- 독립 프런트엔드·네이티브·업스트림·패키징 검토에서 재현된 문서 손상·정보
  노출·릴리스 차단 결함을 해결합니다. 실제 실패 회귀와 수정 후 성공을 기록합니다.
- 같은 최종 후보·실행에서 모든 필수 소스 릴리스 검사를 통과합니다.
  세 브라우저, 두 Windows의 네이티브·암호·인쇄, 설치 MSIX·CLI, 전체 파일
  일치·소스 증거·공개 파일 해시를 확인합니다.
- x64와 ARM64를 각각 실제 네이티브 Windows에서 빌드·실행하며 설치된 MCP
  서버의 문서 작업과 별도 작업자 동작을 확인합니다. 두 아키텍처의 소스 MSIX와
  Store 식별자 MSIX 모두 선택 검사를 포함한 전체 WACK를 통과해야 합니다.
- 릴리스 노트는 지원 범위·한계를 정확히 설명합니다. 후보와 Store 패키지를
  정확한 소스 식별자로 보관하고 실제 Published 기준으로 API 제출합니다.
  제출 식별자와 패키지 두 개의 아키텍처·버전을 API에서 다시 확인합니다.
  무료 가격과 인증 후 자동 공개 설정을 확인합니다.

## 작업 원칙

Store는 API로 작업합니다. Source64 원본과 역사적 증거를 보존합니다.
인쇄 기준·허용 오차·네이티브 창 소유권·필수 검증·무료 러너 조건을 유지합니다.
개인 Cloudflare 계정과 기존 Git 빌드를 사용하며 이번 새 Store 제출은 인증
통과 후 자동 공개합니다. 접수·인증·실제 공개 완료는 따로 확인합니다. WACK
선택 검사 결과를 숨기지 않습니다. 필수 검사 통과는 전체 WACK 성공이나 Store
인증을 뜻하지 않습니다.

검증은 명시한 후보와 실제 수행한 시나리오에 적용됩니다. 모든 문서·프린터와
앞으로 바뀔 런타임의 무결함을 보장하는 표현은 사용하지 않습니다.
